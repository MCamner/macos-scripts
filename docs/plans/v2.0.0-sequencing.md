# v2.0.0 Sequencing — Toward a Governed mqlaunch Runtime

**Status:** Planned
**Target release:** `v2.0.0`
**Theme:** Stop shipping three overlapping runtimes; ship one governed runtime
with an explicit migration boundary.
**Owner:** `mqlaunch`

Linked from [ROADMAP.md](../../ROADMAP.md). This doc sequences the architecture
remediation workstreams (owners, dependencies, gating, risk) that together gate
the `v2.0.0` cut. The per-initiative detail lives in its own plan; this is the
ordering layer above them.

Grounded in the codebase audit (2026-07-05) and verified runtime facts in
[P1-runtime-authority.md](P1-runtime-authority.md).

dependency, not by wish. `Not before` names the earliest gate a phase may start;

## Gating rules (Not before)

* **Phase 12 must not start before Phase 11a.** Deleting v1 while the monolith
  still owns performance/git/network logic risks migrating behavior into the
  wrong place. First give each concern a live home, then cut v1.
* **No phase past 10 may reintroduce a v1 dependency.** Once the freeze
  (Phase 10) is in effect, any new live→v1 edge is a regression, not debt.
* **v2.0.0 must not cut before Phase 12 is green** — i.e. no live path reaches
  `terminal/mqlaunch-v1/`, verified by a lint/test that fails on the forbidden
  dependency direction.

## Risk register

| ID | Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- | --- |
| R1 | Migrating performance off v1 changes observed metrics/output | Medium | High | Snapshot current `mq-performance-menu` output as a golden test before Phase 12; diff after |
| R2 | Monolith de-layering (11a) silently changes launcher behavior | Medium | High | Move one concern per PR; keep `headless-smoke` + selftest green each step; no batching |
| R3 | Hidden fallback path reaches v1 after the freeze | Medium | Medium | Add a CI check that greps live menus/launchers for `mqlaunch-v1` and fails (Phase 10 deliverable) |
| R4 | `eval → "$@"` (11b) alters argument parsing for existing users | Low | Medium | Treat as a flagged behavior fix, not a refactor; document in changelog |
| R5 | Scope creep turns v2.0.0 into a rewrite | Medium | High | Out-of-scope list in [P1-runtime-authority.md](P1-runtime-authority.md) is binding; no UI redesign, no new features |
| R6 | Bridges deleted while still carrying live traffic | Low | High | Remove a bridge only after grep proves zero live callers; reclassify before delete |

## Definition of done (v2.0.0)

`v2.0.0` may be cut only when all of the following hold:

* [ ] Phases 9–12 complete and their exit criteria met
* [ ] `docs/AUTHORITY_MAP.md` is current and classifies every runtime path
* [ ] No live menu or launcher sources `terminal/mqlaunch-v1/*` (CI-enforced)
* [ ] `terminal/mqlaunch-v1/` is either deleted or classified `DEPRECATED` with no live reachability
* [ ] `mqlaunch.sh` is orchestration-first; rendering, git, network, obsidian, and recommendations concerns have named owners outside the monolith
* [ ] One dashboard/UI authority; no duplicate rendering logic
* [ ] Command-surface `eval` on user input replaced with array passing
* [ ] Silent error swallowing on live paths replaced with debug-gated logging
* [ ] `scripts/install-smoke.sh` and all smoke tests green

---

## Expected outcome

At `v2.0.0`, mqlaunch is one governed runtime: a thin launcher that orchestrates
a single live menu/UI/library layer, with no hidden legacy runtime and no
guesswork about where a change belongs.
